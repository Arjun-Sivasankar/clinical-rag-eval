# clinical-rag-eval

A biomedical question-answering RAG pipeline on PubMedQA, built to measure what each retrieval
stage adds: BM25 vs dense vs Qdrant hybrid vs hybrid + cross-encoder reranking. It reports
retrieval metrics, paired significance tests and per-stage latency, all on one laptop GPU.

**Status:** retrieval (M1) and reranking (M2) are done. Generation with vLLM, RAGAS, the
validated LLM judge, Langfuse tracing and the API come next; see the
[milestones](https://github.com/Arjun-Sivasankar/clinical-rag-eval/milestones).

Generated by `python -m clinical_rag.report` from `results/m1_retrieval.json` and
`results/m2_rerank_*.json`; per-query rankings are in `results/runs/`. Hardware: RTX 5060 Laptop
GPU (8 GB), Windows 11, Qdrant 1.20.0 in Docker on the same laptop. Latency is one query at a
time (batch size 1), with the systems of one results file interleaved query by query;
end-to-end = query encoding + Qdrant search + reranking, encoders and rerankers in fp16.

**Headline:** hybrid search + MedCPT reranking of parent abstracts raises Recall@1 from 0.793
(BM25) and 0.843 (hybrid) to 0.892, at 182 ms p95 end to end on a laptop GPU.

What the numbers say (paired bootstrap 95% CIs and exact McNemar tests on the per-query runs,
in `results/m1_significance_*.json` and `results/m2_significance_*.json`; "Holm" is the McNemar
p-value adjusted for the six comparisons of its family, in `results/m*_significance_holm.json`):

- **Hybrid clearly beats BM25:** hybrid DBSF +5.0 points of Recall@1 (CI [+3.0, +7.0], Holm
  p = 6e-6), hybrid RRF +3.6 (Holm p = 7e-4).
- **The smaller steps are suggestive, not conclusive.** Dense vs BM25 +2.9 (CI [+0.5, +5.3],
  p = 0.021, Holm 0.086); hybrid DBSF vs dense +2.1 (CI [+0.3, +3.8], p = 0.029, Holm 0.088);
  DBSF vs RRF +1.4 (CI [+0.1, +2.8] but p = 0.054, Holm 0.11; mixed evidence). Hybrid RRF vs
  dense shows no difference (+0.7, p = 0.50).
- **A domain reranker helps most.** MedCPT on parent abstracts adds +4.9 points of Recall@1
  over hybrid DBSF (CI [+3.0, +6.8], Holm p = 4e-6) and +3.0 points of nDCG@10. MiniLM-L6 on
  abstracts adds +2.1 (p = 0.04, Holm 0.12: not conclusive); bge-reranker-base on abstracts
  does not beat the hybrid base (-1.2, p = 0.33).
- **Rerank whole abstracts, not chunks.** For every reranker, scoring the parent abstract beats
  scoring chunks on their own (Recall@1 +2.0 for MedCPT, p = 0.021; +3.2 for MiniLM, p = 2e-4;
  +17.1 for bge-reranker-base, p = 3e-31; `results/m2_significance_parent_vs_chunks.json`).
  Chunk-level bge-reranker-base drops Recall@1 to 0.660: it ranks short, context-free sections
  (for example a section reading only "Palliative care clinic.") above the gold abstract.
- **BM25 needs the right length normalisation.** fastembed's `Qdrant/bm25` assumes an average
  document of 256 tokens; chunks here average 42.4. With the corpus mean, BM25 Recall@1 rose
  from 0.782 to 0.793 (#17).

### Caveats

- PubMedQA questions are derived from article titles, and the contexts are the same articles'
  abstracts without their conclusions, so lexical overlap is high and BM25 is a strong baseline.
- MedCPT was trained on PubMed search logs, so it may have seen these articles in training; the
  gain is real on this benchmark but may be smaller on unseen clinical text.
- There is no separate dev set: all variants were run on the same 1,000 questions and **all** are
  reported. The one choice made from these results is hybrid DBSF as the base for reranking.
- Re-running the same system changes about 1 of 1,000 rankings (approximate HNSW search, fp16),
  and rebuilding the index can move dense results by a few queries.
- Latency is measured on a shared laptop. Systems in one results file see the same machine
  state; latencies from different files can differ by 10-20 ms.

## How it works

- **Data:** the 1,000 expert-labelled PubMedQA questions (`pqa_labeled`) are the queries, each
  with one gold abstract. The corpus pools the abstracts of `pqa_labeled` + `pqa_unlabeled`
  (62,249 abstracts), so every question has ~62k distractors.
- **Hierarchical chunking:** one chunk per labelled abstract section (BACKGROUND, METHODS,
  RESULTS, ...), long sections split into windows of whole sentences (max 200 words):
  207,664 chunks, 60 words on average. Scoring is per abstract (best chunk per PMID).
- **Qdrant:** one collection, a named dense vector (`BAAI/bge-small-en-v1.5`, 384-d, cosine) and a
  named sparse vector (fastembed `Qdrant/bm25`, length-normalised by the corpus mean, IDF applied
  by Qdrant) per chunk. Hybrid search is one `query_points` call with two prefetches (top 100
  each) fused by RRF or DBSF.
- **Reranking:** a cross-encoder scores (question, passage) pairs in one batched fp16 pass, either
  the top 50 chunks (`+rerank`) or the top 20 distinct parent abstracts (`+rerank_parent`).
- **Indexing cost** (`results/m1_corpus_and_indexing.json`): dense embedding of 207,664 chunks
  137 s on the RTX 5060, BM25 encoding 22 s on CPU, upload to Qdrant 93 s.

## Reproduce

Requirements: Python 3.12, [uv](https://docs.astral.sh/uv/), Docker, an NVIDIA GPU with CUDA 12.8+
drivers (CPU works, slower). From the repo root:

```bash
uv venv --python 3.12 .venv
uv pip install --python .venv/Scripts/python.exe torch --index-url https://download.pytorch.org/whl/cu128
uv pip install --python .venv/Scripts/python.exe -e ".[dev]"
docker compose up -d qdrant

python -m clinical_rag.cli prepare          # download PubMedQA, chunk -> data/
python -m clinical_rag.cli index            # embed + load Qdrant
python -m clinical_rag.cli eval-retrieval   # M1 -> results/m1_retrieval.{json,md}
python -m clinical_rag.cli eval-retrieval --reranker ncbi/MedCPT-Cross-Encoder \
  --systems hybrid_dbsf,hybrid_dbsf+rerank,hybrid_dbsf+rerank_parent \
  --name m2_rerank_MedCPT-Cross-Encoder     # M2; same for the other two rerankers
python -m clinical_rag.significance results/runs/m1_retrieval_bm25.jsonl \
  results/runs/m1_retrieval_dense.jsonl     # paired tests: base run, then compared runs
python -m clinical_rag.significance holm results/m2_significance_vs_hybrid_dbsf.json  # Holm
python -m clinical_rag.report               # results table -> results/summary.md and README
```

Or `make eval` (Git Bash or Linux/macOS). Use `.venv/bin/python` on Linux/macOS. Settings come
from environment variables (`QDRANT_URL`, `CRAG_DENSE_MODEL`, `CRAG_DEVICE`, ...; see
`src/clinical_rag/config.py`). Tests run without downloads or a GPU (in-memory Qdrant, fake
encoders): `python -m pytest -m "not slow"`.

## Layout

```
src/clinical_rag/   data.py chunking.py encoders.py index.py retrieve.py rerank.py
                    metrics.py evaluate.py significance.py report.py cli.py
results/            metrics JSON + Markdown per run, significance tests, summary.md,
                    runs/*.jsonl (gold rank and top 10 per query)
tests/              pytest suite (data, chunking, metrics, retrieval, reranking, significance)
```
